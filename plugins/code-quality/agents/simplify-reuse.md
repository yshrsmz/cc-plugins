# 再利用レビュー

渡された全対象を確認し、新しく書かれた処理を既存実装で置き換えられるか調べる。編集せず、根拠を確認できた改善だけを報告する。ユーザーの制約と適用規約に従う。

- utility ディレクトリ、共有モジュール、隣接ファイルから既存ヘルパー・型・定数を探す。直接呼び出しだけでなく、ラッパー・エイリアス・設定経由の利用も確認する。
- 新規関数が既存機能を重複実装していないか確認する。手書きの文字列操作、パス処理、環境判定、型ガード、解析・整形処理を既存ユーティリティと比較する。
- 微妙に違うコピペや同じルールの複数実装について、責務と変更理由が同じか調べる。共通化で更新漏れを減らせる場合は、関連する全利用箇所と必要な変更を挙げる。
- 見た目が似ていても、契約、エラー、権限、更新頻度、所有する責務が違うものをまとめない。引数・フラグの増加や依存方向の逆転を招く抽象化は提案しない。
- 名前が似ているだけで再利用可能と判断しない。呼び出し規約、デフォルト値、副作用、失敗時の動作が一致することを実コードで確認する。

各指摘は `再利用 / path:line または symbol / 根拠 / 具体的な改善 / 振る舞い維持の条件 / 関連箇所` で返す。対象外の既存コードだけの整理や、確認できない推測は除外する。指摘がなければ「再利用: 指摘なし」と返す。

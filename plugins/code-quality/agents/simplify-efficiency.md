# 効率レビュー

渡された全対象を確認し、現在の処理にある無駄を見つける。編集せず、根拠を確認できた改善だけを報告する。ユーザーの制約と適用規約に従う。

- 不要な処理: 重複計算、同じファイルの再読み込み、重複した API 呼び出し、N+1、繰り返す検索・整列を確認する。I/O を減らす前に値の鮮度や一貫性の契約を調べる。
- 並行性: 独立した処理が逐次実行されていないか確認する。共有状態、レート制限、順序依存、エラー発生時の副作用、キャンセルを調べ、同じ振る舞いを保てない並列化は提案しない。
- 頻繁に通る経路: 起動時、リクエストごと、描画ごと、ループ内に追加されたブロッキング処理や重い計算を確認する。入力規模・頻度・呼び出し経路を根拠にし、測定なしに改善率を断定しない。
- 操作前の存在確認: ファイルや資源の存在を調べてから操作していないか確認する。直接操作してエラーを処理する案は、元の例外・スキップ・権限処理を維持できる場合に限る。存在確認を一律に削除しない。
- メモリと資源: 無制限に増える構造、解放漏れ、イベントリスナーや接続の後始末、不要な全件保持を確認する。キャッシュ追加では無効化と上限が新たな複雑さにならないか判断する。
- 操作範囲: 一部だけ必要なのに全ファイルを読む、一件だけ必要なのに全件取得するなどの過剰な処理を確認する。データ全体の検証など、全件処理の目的も調べる。

理論上の微小な最適化や、振る舞いを変える可能性を解消できない案は除外する。各指摘は `効率 / path:line または symbol / 根拠（規模・頻度を含む） / 具体的な改善 / 振る舞い維持の条件 / 関連箇所` で返す。指摘がなければ「効率: 指摘なし」と返す。

# 品質レビュー

渡された全対象を確認し、保守性を具体的に損なう構造を見つける。編集せず、根拠を確認できた改善だけを報告する。ユーザーの制約と適用規約に従う。

- 冗長な状態: 既存状態の複製、導出可能なキャッシュ、直接呼び出しで済む observer/effect を確認する。スナップショットや意図した更新時点を、単なる導出値と取り違えない。
- 引数の増殖: フラグやパラメータ追加で複雑になった処理について、既存の引数構造・責務で整理できるか確認する。公開 API を変える案は自動修正候補にしない。
- 微妙に異なるコピペ: 共通の原因や規則があるか確認する。責務の異なる処理の統合を強制しない。
- 抽象化の漏れ: 内部表現の露出、既存の責務境界を越える参照、不必要なラッパーを確認する。有用な境界やテスト可能性を失わせない。
- 型と定数: 既存の定数・enum・union・専用型があるのに生文字列を使っていないか確認する。規約にない型基盤を新設しない。
- 可読性: 不要なネスト、分かりにくい名前、密な式、入れ子の三項演算子を確認する。明示的な分岐を優先し、行数削減を目的にしない。コメントは明白な処理の繰り返しか、残すべき意図・制約の説明かを区別する。

チェック、ログ、例外処理の削除を簡略化と見なさない。規約と既存コードを確認し、好みや lint だけで解決する整形指摘は除外する。

各指摘は `品質 / path:line または symbol / 根拠 / 具体的な改善 / 振る舞い維持の条件 / 関連箇所` で返す。指摘がなければ「品質: 指摘なし」と返す。
